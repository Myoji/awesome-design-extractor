# Volvo Global Design Extraction Design

## 목적

Volvo Cars 글로벌 공개 사이트의 렌더링 결과를 근거로 `awesome-design-md` 형식의 재사용 가능한 디자인 시스템 패키지를 `examples/volvo/`에 만든다. 결과물은 관찰된 사실과 추론을 분리하고, 원본 사이트나 보호 자산을 복제하지 않으면서도 다른 코딩 에이전트가 볼보의 시각 언어를 적용할 수 있을 만큼 구체적이어야 한다.

## 기준 소스와 범위

- 시작 URL: `https://www.volvocars.com/intl/`
- 최종 렌더링 URL: 리디렉션이 발생하면 브라우저에서 확인한 URL을 기준으로 기록한다.
- 사이트 범위: `volvocars.com`의 글로벌 공개 페이지 중 `/intl/` 경로를 우선한다.
- 페이지 예산: 최대 20페이지, 기본 깊이 2의 적응형 크롤링.
- 대표 페이지: 홈, 차량 목록/상세, 전동화, 안전, 지속가능성, 구성 또는 구매 진입, 지원·서비스, 콘텐츠 페이지.
- 제외 대상: 로그인·계정, 결제·주문 제출, 법률·개인정보·쿠키 정책, 반복되는 지역 페이지, 외부 소셜/미디어 사이트.
- 기본 뷰포트: 데스크톱 약 `1440 x 1000`, 모바일 약 `390 x 844`.

## 산출물

`examples/volvo/` 아래에 다음 파일을 만든다.

- `EVIDENCE.md`: 소스, 방문·실패·제외 URL, 렌더링 환경, 측정값, 관찰/추론/불확실성, 9개 섹션 완성도 평가와 한계를 기록한다.
- `DESIGN.md`: Visual Theme부터 Agent Prompt Guide까지 9개 섹션으로 디자인 규칙을 정리한다.
- `preview.html`: 외부 네트워크 의존성이 없는 라이트 모드 정적 카탈로그를 만든다.
- `evidence-summary.json`: 방문 페이지와 핵심 토큰·컴포넌트·반응형 관찰을 기계 판독 가능한 형태로 요약한다.
- `aggregate-insights.json`: 페이지별 측정값을 역할 중심 토큰과 반복 패턴으로 집계한다.
- `preview-qa.json`: 데스크톱·모바일 렌더링 결과, 오버플로, 필수 섹션, 로컬 링크와 메타데이터 검증 결과를 기록한다.

원본 사이트에 독립적인 다크 모드가 있거나 반복되는 다크 표면만으로 별도 토큰 세트를 신뢰성 있게 추출할 수 있을 때만 `preview-dark.html`을 만든다.

## 증거 수집 구조

1. 홈을 데스크톱으로 렌더링해 최종 URL, 내비게이션, 쿠키 배너, 동일 출처 링크와 대표 컴포넌트를 확인한다.
2. 9개 완성도 섹션에서 부족한 부분을 기준으로 다음 페이지를 선택한다.
3. 각 페이지에서 색상, 글꼴, 타이포 스케일, 간격, 경계, 반경, 그림자, 그리드, 반복 컴포넌트를 제한된 DOM·computed style 읽기로 수집한다.
4. 홈과 대표 차량·콘텐츠·폼/구매 진입 페이지를 모바일로 재방문해 데스크톱 규칙에 대한 반응형 오버라이드를 기록한다.
5. 메뉴, 버튼, 링크, 탭, 아코디언 등 단순하고 결정적인 상호작용만 실행해 상태 변화를 확인한다. 외부 제출이나 계정·구매 상태 변경은 하지 않는다.
6. 직접 확인한 값은 `observed`, 반복 패턴을 통한 의도 해석은 `inferred`, 표본 부족이나 충돌이 있는 내용은 `uncertain`으로 분류한다.

데스크톱을 기본 디자인 시스템으로 사용하고 모바일 차이는 오버라이드 또는 모바일 변형으로 기록한다. 데스크톱이 비정상적으로 렌더링되는 경우에만 `EVIDENCE.md`에 예외 근거를 남기고 모바일을 우선한다.

## 프리뷰 설계

`preview.html`은 마케팅 페이지 복제가 아니라 디자인 시스템 카탈로그다. 다음 섹션을 포함한다.

- Overview
- Reconstruction
- Tokens
- Components
- States
- Layout
- Responsive
- Limitations

Reconstruction에는 헤더/히어로, 차량 탐색 또는 모델 카드, 전동화·안전 콘텐츠 모듈, 지원/구성 진입 흐름, 푸터처럼 실제로 관찰된 조합만 사용한다. 각 샘플은 사용한 컴포넌트 태그와 증거 등급을 표시한다.

차량 사진, 로고, 브랜드 아트워크는 재사용 가능한 자산으로 복제하지 않는다. 볼보의 표면 문법을 보여주기 위해 관찰된 색상, 크롭 방향, 명암, 섹션 밴드, 재질감과 중립 기하를 이용한 CSS 기반 대체 표면을 우선한다. 작은 보호 참조 이미지가 꼭 필요한 경우에만 `assets/`에 두고 `data-asset-role`, `data-reuse="forbidden"`, 출처 URL, 캡처 날짜, 비제휴 고지를 모두 표시한다.

## 실패와 한계 처리

- 접근 실패는 `auth_required`, `bot_protection`, `network_blocked`, `render_timeout`, `blank_or_loading_state`, `tool_unavailable`, `unsupported_interaction` 중 하나로 분류한다.
- 실패 URL, 사용 도구, 대체 시도, 9개 섹션에 미친 영향을 `EVIDENCE.md`에 기록한다.
- 근거가 없는 알림 색상, 포커스 상태, 모션, 다크 모드, 브레이크포인트 수치를 발명하지 않는다.
- 페이지 예산을 소진하거나 남은 약한 섹션을 확인할 공개 페이지가 없으면 그 이유를 종료 조건으로 기록한다.

## 검증과 완료 조건

- `DESIGN.md`가 9개 필수 섹션을 모두 포함한다.
- `EVIDENCE.md`가 감사 메타데이터, URL 범위, 증거 테이블, 데스크톱/모바일 충돌 규칙, 완성도 평가, 법적·범위 메모를 포함한다.
- `preview.html`이 필수 8개 카탈로그 섹션과 상대 링크를 포함하고 외부 의존성 없이 열린다.
- 모든 재구성 샘플에 컴포넌트 태그와 `observed`/`inferred`/`uncertain` 레이블이 있다.
- 데스크톱과 모바일 렌더링에서 본문 수준의 의도하지 않은 가로 오버플로가 없다.
- 모바일에서 텍스트, 버튼, 탭, 카드, 토큰 표가 부모 영역을 벗어나지 않는다.
- 저장소의 프리뷰 검증 스크립트와 관련 정적 검사를 통과한다.
- 기존 미커밋 변경인 `scripts/validate-preview-catalog.mjs`와 `examples/mercedes-benz/`는 수정하거나 커밋하지 않는다.
